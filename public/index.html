Automation Studio 使用說明

              
從建立專案、錄製操作、參數化、測試除錯，到批次執行與發布，用一頁快速掌握完整工作方式。

            

            

          


          

            
快速上手流程
建議第一次使用時依照下列順序操作。

            

              
1建立專案輸入專案名稱與入口網址
→
              
2設定工作站允許網域、瀏覽器與登入方式
→
              
3錄製操作人工操作轉成可編輯流程步驟
→
              
4整理流程調整 selector、等待與參數
→
              
5測試 Debug確認步驟、變數、下載與錯誤
→
              
6批次／發布重複執行或輸出可攜成果

            

          


          

            

              
主要操作說明
依功能頁面快速找到正確操作方式。

              

                
站
網站與工作站
先設定入口網址與允許網域。需要人工登入、MFA 或驗證碼時，建議使用可見瀏覽器；若要接管已登入 Chrome，使用 CDP 模式。
舊式 Frame／SmartKMS 網站如何錄製？
V1.2.1 保留 V1.1.6 的多 Frame 錄製與事件保留機制：錄製事件使用 Playwright Binding、Frame Bridge 與 Console Beacon 備援，工作站事件清單使用 Server-Sent Events 即時串流。SmartKMS 事件會保留子 Frame 路徑，並在必要時使用跨 Frame fallback。

                
流
自動化設計器
錄製後逐步檢查步驟名稱、selector 與等待條件。重複元件可使用 first／last／nth；動態頁面宜加入「等待顯示」而非只使用固定秒數。

                
參
參數與資料
把年度、階段、報表名稱等可變內容改成參數。固定選項使用下拉選單；相依欄位可使用父子下拉，批次任務會沿用相同參數定義。

                
測
測試與 Debug
先選擇適合的執行範圍驗證流程；執行失敗時可用內建 AI 分析，或下載遮罩後的診斷包提供外部 AI／支援人員。

                  

                    

                      步驟執行方式
                      

                        
執行完整流程：從第 1 步一路執行到最後，適合最終驗收。

                        
只執行此步驟：只測目前選取步驟，適合 selector、點擊、輸入、下載等單點 Debug；巢狀子步驟也可直接執行。

                        
從此步驟執行：從目前選取位置接續同層後續步驟，再銜接外層後續流程。

                        
    
                          
  1. 先到「自動化設計器」選取步驟。
    2. 
                          
  2. 單步或從中段開始不會自動重跑前置登入、搜尋、導頁或建立變數，請先準備正確瀏覽器與資料狀態。
    3. 
                          
  3. 需要 {{參數}} 的步驟仍使用「測試參數」；若依賴前置流程變數，建議先跑完整流程。
    4. 
                          
  4. 測試後用執行監控與 Debug 分頁確認錯誤、Console、Network、Popup／Download 與變數。
    5. 
                        

                        
巢狀流程：直接從條件／迴圈內子步驟開始時，不會重新執行外層條件判斷或之前的迴圈次數；若要完整語意，請選取父步驟。

                      

                    

                    

                      執行失敗後：AI 分析與失敗診斷包
                      

                        
AI 分析失敗原因：失敗後整理錯誤、失敗步驟、selector、Console／Network／Popup／Download 與頁面摘要，交由目前 AI Provider 分析根因與修正建議。

                        
候選步驟修正：AI 可建議 timeout、等待條件、iframe、matchMode、下載模式或 selector；新的 selector 必須來自失敗頁面實際觀察證據。確認後再按「套用候選修正」，並先用「只執行此步驟」重測。

                        
下載失敗診斷包：輸出遮罩後 ZIP，包含執行摘要、失敗步驟、近期事件、頁面文字／元素摘要、selector 候選與失敗截圖，方便外部 AI 或支援人員分析。

                        
    
                          
  1. 執行失敗後先按「AI 分析失敗原因」。
    2. 
                          
  2. 確認候選修正合理後套用，再單步重測。
    3. 
                          
  3. 若仍無法判斷，再下載診斷包 ZIP；提供外部 AI 前請自行檢查內容。
    4. 
                        

                        
機敏資料：診斷包會遮罩 Cookie、Authorization、API Key、密碼、URL query value 與流程變數值，但截圖或頁面可見文字仍可能包含業務資訊，分享前請依組織規範檢查。

                      

                    

                  

                

                
批
批次任務
建立多筆參數組合後依序執行。需要人工登入的流程，建議只保留一個穩定的人工登入檢查點，後續批次可沿用同一瀏覽器工作階段。

                
發
發布與版本
確認入口網址、允許網域與啟用步驟後，再輸出可攜工作流程、TypeScript 或 SKILL.md。匯出時不會攜出密碼、Cookie 或瀏覽器 Profile。
系統版本與專案版本怎麼區分？
Automation Studio 系統版本採 MAJOR.MINOR.PATCH：重大不相容變更升 MAJOR、新增一組使用者功能升 MINOR、修正與小幅改善升 PATCH。目前系統版本為 1.2.1。專案版本號則屬於個別工作流程，可由使用者自行管理，兩者互不影響。

  1. 元件找不到：確認 selector 是否使用動態 class／id，優先使用文字、label、role 或穩定屬性。
    2.

    3.

    4. 
                
  4. PDF 只開預覽：可使用下載步驟或啟用「PDF 直接下載，不開啟預覽」。
    5. 
                
  5. 批次第二筆失敗：檢查是否重複執行登入、關閉分頁或破壞共用瀏覽器工作階段。
    6. 
              

            

          


          

            
常見問題 FAQ
點擊問題即可展開答案。

            

              
為什麼錄製成功，但重新執行時找不到按鈕？
通常是 selector 過度依賴動態 class、暫時 id 或頁面尚未完成載入。建議在自動化設計器改用穩定文字／role／label，並在前一步加入適當等待。

              
帳號、密碼、Cookie 會被匯出嗎？
不會。專案匯出會移除敏感預設值，也不包含瀏覽器 Profile、Cookie 或登入工作階段。登入與 MFA 建議由使用者在瀏覽器中人工完成。

              
CDP 模式與 Automation Studio 管理瀏覽器有什麼差別？
管理模式由系統建立專用瀏覽器與 Profile；CDP 模式接管本機已開啟的 Chrome，適合需要沿用既有登入狀態的網站。流程結束時只解除控制，不會主動關閉外部 Chrome。

              
為什麼下載 PDF 時只看到預覽頁？
Chrome 可能使用內建 PDF Viewer。可在網站與工作站啟用「PDF 直接下載，不開啟預覽」，或將流程步驟改成下載並使用 auto/click 模式。

              
批次任務中需要每筆都重新登入嗎？
通常不需要。若流程設計為單一人工登入檢查點，批次工作可重用同一瀏覽器工作階段；但網站若主動登出或登入逾期，仍可能需要重新驗證。

              
如何判斷錯誤發生在哪裡？
先看「測試與 Debug」的執行錯誤與步驟結果，再依情況查看 Console、Network、Popup/Download 或變數。歷史任務也可在「執行紀錄」展開詳情查看。

              
「只執行此步驟」與「從此步驟執行」有什麼差別？
「只執行此步驟」只測目前選取的單一步驟；「從此步驟執行」會從選取步驟開始繼續執行後續流程。兩者都不會自動重跑選取步驟之前的登入、導頁、搜尋或變數建立，因此使用前要先準備好正確的瀏覽器與資料狀態。

              
可以把一份流程搬到另一台電腦嗎？
可以，使用「發布與版本」輸出可攜工作流程 ZIP，再由另一台 Automation Studio 匯入。登入狀態、帳密與本機 Profile 不會一起移轉。

              
如何使用「發布與版本」輸出的 TypeScript 專案獨立執行？需要哪些 Node.js 套件？
                
發布時勾選 TypeScript 後，匯出的 typescript-project 資料夾本身就是可獨立執行的 Playwright 專案，不需要再開啟 Automation Studio。此版本實際需要的 npm 套件只有 playwright；不需要另外安裝 typescript 或 ts-node，因為 start.bat 會使用 Node.js 的 --experimental-strip-types 直接執行 src/run.ts。

                
    
                  
  1. 準備 Node.js：建議使用 Node.js 22.6 以上，優先使用目前公司核准的 Node.js 22／24 LTS 64 位元版本。安裝後在命令提示字元執行 node -v 與 npm -v 確認可用。
    2. 
                  
  2. 取得 Node.js：可由 Node.js 官方網站下載 Windows 安裝版；公司電腦若無管理者權限，可使用資訊單位提供的軟體中心，或下載官方 Windows ZIP 版解壓縮後使用，並將該資料夾加入目前工作階段的 PATH。
    3. 
                  
  3. 安裝專案套件：解壓縮發布檔後進入 typescript-project 資料夾，執行 npm install。npm 會依 package.json 下載本專案指定的 playwright 套件。
    4. 
                  
  4. 準備瀏覽器：若流程使用 Playwright 隨附 Chromium，再執行 npx playwright install chromium。若專案設定使用本機 Chrome，且 Chrome 已安裝，通常不需要下載 Chromium。
    5. 
                  
  5. 設定參數：若匯出內容有 parameters.example.json，可複製成 parameters.json 後填入需要的值；沒有提供的參數則會沿用流程中非敏感的預設值。密碼、Cookie、MFA 等敏感資料不會被發布檔自動帶出。
    6. 
                  
  6. 執行：Windows 可直接執行 start.bat；也可在命令列執行 npm start。流程若包含人工登入、MFA 或驗證碼，仍需依流程設計人工完成。
    7. 
                

                
離線／內網環境：如果執行電腦無法連到 npm 或 Playwright 下載站，應先在可連網環境完成 npm install 與需要的瀏覽器安裝，再依單位軟體供應政策準備離線套件；不要為了繞過公司憑證而關閉 TLS 驗證。

              

              
遇到無法自行排除的問題怎麼辦？
使用左側「回報問題」，填寫重現步驟與實際結果。系統會建立寄到預設支援信箱的郵件內容；必要時可另外附上不含敏感資料的畫面截圖。
